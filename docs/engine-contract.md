# Engine Contract

The engine is the source of truth for operations that mutate PDF structure.
The browser editor can preview edits, but engine output decides whether a
feature is real.

## Payload

```json
{
  "pdfBase64": "<source bytes>",
  "password": "<optional password>",
  "pages": [
    {
      "sourceIndex": 0,
      "sourcePdfBase64": "<optional donor PDF bytes for external insertion>",
      "password": "<optional donor password>",
      "rotation": 0,
      "width": 612,
      "height": 792,
      "cropBox": { "x": 0, "y": 0, "width": 1, "height": 1 }
    }
  ],
  "operations": [],
  "metadata": {},
  "saveOptions": {
    "annotationMode": "flatten",
    "redactionMode": "textOnly",
    "flattenForms": false,
    "sanitize": false,
    "sanitizeOptions": {
      "metadata": true,
      "xmlMetadata": true,
      "embeddedFiles": true,
      "fileAttachmentAnnotations": true,
      "javascript": true,
      "javascriptNameTree": true,
      "annotationActions": true,
      "comments": true,
      "hiddenLayers": true,
      "embeddedSearchIndex": true,
      "staleIncrementalUpdates": true,
      "unreferencedObjects": true,
      "links": true,
      "thumbnails": true,
      "resetFormFields": false
    },
    "validate": true,
    "encrypt": false,
    "userPassword": "",
    "ownerPassword": "",
    "permissions": {
      "print": false,
      "copy": false,
      "annotate": false,
      "form": false
    }
  }
}
```

## Engine-Required Operations

- Existing text replacement.
- Redaction.
- Native annotation export.
- Password-backed PDFs.
- Existing annotation delete/replace.
- AcroForm field fill, basic field creation, and flatten.
- Page organization operations: reorder/duplicate via `pages`, blank page
  insertion with `sourceIndex: -1`, external PDF page insertion with
  `sourcePdfBase64`, `cropPage`, and `resizePage`.
- Existing image replacement through destructive `deleteImage` followed by a
  real `image` insertion.
- Existing image movement through `moveImage`, which extracts the source image,
  redacts the original visual area, and inserts the image at the target rect.
- Source vector removal through `deleteVector`, which applies PDF redaction with
  graphics removal instead of leaving an overlay-only mask.
- Literal, regex, and whole-page redaction through `redactSearch` and
  `redactPage`.
- File attachment comments through `fileAttachment`, written as real
  FileAttachment annotations.
- Typed, drawn, and image signature appearances as visible page content.
- Existing annotation flatten when `annotationMode` is `flatten`.
- Semantic text reflow generated by the browser layout model.
- Hidden-info sanitization when `saveOptions.sanitize` is true.
- User/owner password encryption and permission flags through `saveOptions`.
- Preflight reporting through `/api/pdf/preflight` or `pdf_engine.py preflight`.
- Searchable OCR export through `/api/pdf/ocr` or `pdf_engine.py ocr`.
- OCR correction for scanned image-over-text pages through
  `/api/pdf/ocr-correct` or `pdf_engine.py ocr-correct`.
- Certificate-backed CMS digital signing through `/api/pdf/cert-sign` or
  `pdf_engine.py cert-sign`.
- Basic accessibility reporting and repair, compare report PDFs, form XFDF
  import/export, signature validation, OCR status checks, and batch actions are
  available through CLI/API commands. Future timestamp/LTV signature trust, full
  PDF/UA repair, PDF/A/X preflight fixups, interactive visual compare overlays,
  and production action queues remain engine gaps.

## Page Organization Operations

The `pages` array is the primary page-order contract. Existing pages are copied
from `sourceIndex`; repeated source indexes duplicate pages; `sourceIndex: -1`
creates a blank page using optional `width` and `height` point values. A page
item may include `sourcePdfBase64` and a `sourceIndex` to insert a page from a
different PDF. A page item may include `cropBox` for an initial crop.

`cropPage` uses normalized page coordinates and persists a PDF crop box.
`resizePage` uses `targetWidth` and `targetHeight` point values and persists the
PDF media/crop box. These operations are structural page edits; they are not
implemented by screenshot export.

## Redaction Operations

`redactSearch` supports literal text search or regex word matching when
`regex: true`. `redactPage` removes visible content across the full page. Both
paths use PDF redaction annotations followed by `apply_redactions`, then a full
garbage-collecting save. Tests assert that removed secrets are absent from text
extraction and raw PDF bytes.

## Compare And Batch Commands

`pdf_engine.py compare --input before.pdf --other after.pdf --stdout` returns a
JSON report with page counts, changed page indexes, text previews, render delta
metrics, and normalized changed-area regions for render differences. `--report
compare.pdf` also writes a compact PDF report. It is not yet an interactive
visual overlay UI or annotation/object diff engine.

`pdf_engine.py batch --manifest manifest.json --stdout` runs multiple apply jobs
from a manifest:

```json
{
  "jobs": [
    {
      "input": "input.pdf",
      "output": "output.pdf",
      "payload": { "operations": [], "saveOptions": { "validate": true } }
    }
  ]
}
```

Each job writes an output PDF and returns per-job validation. The regression
suite includes a 100-output manifest run. This is a local engine action runner,
not yet a queued production worker or saved action-builder UI.

## Semantic Reflow Operations

The browser owns layout solving and sends concrete operations to the engine.
For moved source text, the payload contains searchable `text` operations. If a
block moves within the same page, the operation includes `eraseOriginal`. If a
block crosses pages, the original page gets a destructive `redact` operation
and the target page gets a separate searchable `text` operation.

The engine must not rasterize text reflow. `flowSlice` remains reserved for
future non-text visual object movement and is not the primary text reflow path.

## Sanitization Options

The current sanitizer removes the hidden data categories exposed through
`sanitizeOptions`: metadata, XMP metadata, embedded files, file-attachment
annotations, comment annotations, annotation actions, JavaScript/action
entries, JavaScript name trees, links/actions, hidden layer catalog entries,
embedded search-index catalog signals, thumbnails, and optionally stored form
values. It also forces a full garbage-collecting rewrite so stale incremental
sections and unreferenced objects are dropped from the saved file.

Sanitization must preserve visible page content unless a redaction operation
explicitly removes it. Hidden layer handling currently removes the OCG/catalog
layer configuration and unreferenced layer objects; it is not a claim that
visible optional-content page artwork is semantically reauthored.

## AcroForm Contract

Form operations support text fields, checkboxes, radio buttons, combo boxes,
list boxes, signature widgets, required flags, default values, export values,
explicit tab order, and flattening. Existing fields are matched by field name or
rectangle. New fields are created when a `formField` operation includes
`"create": true`; the engine writes real PDF Widget annotations through
PyMuPDF, not browser overlay state. Saved widgets must retain appearance streams
so Acrobat, Preview, and Chrome can display the value without recalculating
appearances. When a form operation includes `tabIndex`, the engine writes the
page annotation order and marks `/Tabs /A` so annotation order is the tab
traversal source. Signature fields can be created and later signed through the
certificate-signing command. Newly created radio buttons are widget-backed, but
full interconnected radio group authoring is not claimed yet. XFA is detected
and reported as unsupported.

`pdf_engine.py forms-export --input form.pdf --stdout` emits an XFDF document
containing field names and values. `pdf_engine.py forms-import --input form.pdf
--xfdf values.xfdf --output filled.pdf` writes supported text, checkbox, radio,
combo, and list values back into real AcroForm widgets.

## Signatures And Security

`typedSignature`, `drawnSignature`, and `signatureImage` create visible
signature appearances in page content.

`pdf_engine.py cert-sign` creates a real PDF signature field, writes a `/Sig`
dictionary with `/Filter /Adobe.PPKLite`, `/SubFilter /adbe.pkcs7.detached`,
calculates `/ByteRange`, signs the covered bytes with `openssl cms -sign`, and
fills `/Contents` with a detached CMS signature. `--lock-policy noChanges`,
`formFill`, or `formFillAnnotate` adds a DocMDP `/Reference` and catalog
`/Perms /DocMDP` entry so viewers can enforce certification-style permissions.
`signature-validate` extracts the ByteRange, strips `/Contents` padding, reports
DocMDP lock policy, and verifies the CMS signature with OpenSSL. Tests mutate a
signed PDF and require validation failure, proving the signature covers PDF bytes
rather than acting as a visual-only stamp.

Current boundaries: timestamp authorities, LTV/revocation material, and trusted
enterprise certificate stores are not yet claimed. The current automated
validation proves structural qpdf compatibility, PyMuPDF signed-widget
detection, DocMDP policy encoding, and CMS cryptographic integrity.

When `saveOptions.encrypt` is true, the engine saves with AES-256 encryption,
the supplied user/owner passwords, and conservative permission flags. Validation
receives the relevant password so qpdf and PyMuPDF can reopen the encrypted
output. Password permission behavior must be verified by qpdf and external
viewer smoke before release claims.

## OCR Contract

`pdf_engine.py ocr-status --language eng+kor --stdout` checks for Tesseract,
tessdata, and requested language packs. `pdf_engine.py ocr` renders selected
scanned pages, calls PyMuPDF's Tesseract-backed OCR PDF export, and writes an
image-over-text searchable PDF. Existing text pages are copied by default; pass
`--force` to OCR selected pages even if text extraction already returns content.

OCR output is accepted only after PyMuPDF and qpdf validation. The searchable
text layer must be extractable from the saved PDF; browser-only OCR overlays do
not satisfy this contract. Korean OCR depends on installed `kor` tessdata and is
covered by the Korean correction regression.

`pdf_engine.py ocr-correct` is scoped to scanned image-over-text pages. It
rebuilds corrected pages as image-over-text PDF pages, removes stale OCR text
from those pages by not copying the old content stream, and inserts corrected
invisible text rectangles. It is intended for OCR correction workflows, not
general vector/text PDF editing. Browser OCR correction UI and scanned-PDF
semantic edit mode remain follow-up product work.

## Validation Response

The engine validation response must include:

- `ok`
- `pageCount`
- `encrypted`
- `annotationCount`
- `textLength`
- `pageSizes`
- `qpdfChecked`
- `errors`

When `REQUIRE_QPDF=1`, `qpdfChecked` must be true and qpdf failures are fatal.

`pdf_engine.py validate --input encrypted.pdf --password <password> --stdout`
is the CLI form for encrypted output validation.

## Preflight Response

`/api/pdf/preflight` and `pdf_engine.py preflight` return a JSON object with:

- `validation`
- `warnings`
- `pageCount`
- `metadata`
- `xmpLength`
- `embeddedFileCount`
- `javascriptActionCount`
- `javascriptNameTreeCount`
- `formFieldCount`
- `signatureFieldCount`
- `xfaPresent`
- `explicitTabOrderPageCount`
- `fontCount`
- `hiddenLayerCount`
- `commentAnnotationCount`
- `fileAttachmentAnnotationCount`
- `annotationActionCount`
- `linkActionCount`
- `embeddedSearchIndexCount`
- `staleIncrementalSaveCount`
- `unreferencedObjectSignalCount`
- `pdfaClaim`
- `pdfxClaim`
- `outputIntentCount`
- `fonts`
- `pages`

Each page entry includes page boxes, image/drawing/annotation/widget counts,
and font names. PDF/A/PDF/X fields are claim and output-intent diagnostics only;
this is a basic product preflight, not a PDF/A or PDF/X certification engine.

`pdf_engine.py preflight --input file.pdf --report report.pdf` writes a
human-readable report PDF that mirrors the JSON warnings and metrics.

## Accessibility Report

`pdf_engine.py accessibility --input file.pdf --stdout` returns a basic report
for title/language, tag-structure presence, form fields, page text extraction,
and image alt-text gaps. `pdf_engine.py accessibility-repair` can persist title,
language, basic MarkInfo/StructTreeRoot signals, page tab-order source, and
image object `/Alt` strings. This is basic structural repair evidence, not a
PDF/UA validator or full reading-order/tag-tree authoring system.
